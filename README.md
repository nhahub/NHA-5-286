# AI Test Automation

Black-box AI testing tool: give it a URL and a plain-language requirement; it designs test scenarios, writes Playwright tests, runs them, explains failures, and produces an English report. **No human writes a test.**

> Governing principle: agents reason and propose, tools execute, LangGraph orchestrates, humans approve risky changes.

---

## Setup

### Prerequisites

- Python 3.11+
- Node.js 18+

### 1. Clone and install Python dependencies

```bash
cd ai-test-automation
pip install -e ".[dev]"
```

### 2. Install Node dependencies and Playwright browsers

```bash
npm install
npx playwright install chromium
```

### 3. Configure environment

```bash
cp .env.example .env
# Edit .env — set DEFAULT_MODEL and your API key(s)
```

At minimum set:

```
DEFAULT_MODEL=openai:gpt-4o
OPENAI_API_KEY=sk-...
```

## How to run

### Launch the web UI

```bash
python main.py --ui
```

Open `http://localhost:7860` in your browser. Fill in the URL field and requirements, tick the authorization checkbox, and click **Run**.

### Run headless (CI mode)

```bash
python main.py --headless \
  --url "https://example.com" \
  --requirements "Verify the homepage loads and the login link is visible."
```

### Run tests

```bash
pytest                  # Python unit/contract tests
npx playwright test     # Generated TypeScript specs (requires a run to exist in runs/)
```

## Folder map

| Folder | Contents |
|--------|----------|
| `contracts/` | Pydantic models: `TestRequest`, `Scenario`, `Evidence`, `FailureAnalysis`, `FixProposal`, `ReportModel` |
| `intake/` | URL resolver, safety checks (SSRF guard), model resolver |
| `agents/` | Four LLM agents: Planner, Code Generation, Failure Analyzer, Fix Proposal |
| `prompts/` | Markdown system prompts for each agent |
| `validation/` | Deterministic TypeScript/Playwright API validator (`tsc --noEmit`) |
| `execution/` | Playwright test runner and evidence collector; local `@tool` functions |
| `analysis/` | Evidence normalisation; deterministic failure-class pre-classifier |
| `healing/` | Patch applicator (`apply_fix`); human code-review checkpoint |
| `graph/` | LangGraph `TestRunState`, node wrappers, routing functions, graph builder |
| `llm/` | `init_chat_model` wrapper; Playwright MCP client with per-agent tool filter |
| `report/` | `ReportModel` builder; Jinja2 Markdown/HTML exporters; PDF via Chromium |
| `ui/` | Gradio two-field MVP form with optional LLM configuration section |
| `fixtures/` | Realistic fake data satisfying the contracts (used by `tests/test_fixtures.py`) |
| `test_data/` | Generic test inputs (sample requirements, blocked URLs, model strings) |
| `tests/` | `test_fixtures.py` (working) + one stub test file per module |
| `reference/` | Reserved for architecture documents and decision records |
| `runs/` | Generated at runtime: `runs/<run_id>/` holds specs, results, artifacts, report |

## Run folder layout

Each run writes to `runs/<run_id>/`:

```
runs/run-20261004-abc123/
├── tests/           # .spec.ts files generated by the Code Generation agent
├── artifacts/       # screenshots and traces (on failure)
├── patches/         # unified-diff files from Fix Proposal
├── results.json     # Playwright JSON reporter output
├── analysis.json    # FailureAnalysis from the Failure Analyzer
├── scenarios.json   # test_plan from the Planner
├── report.md        # rendered Markdown report
└── html-report/     # rendered HTML report
```

## Key constraints (from spec)

| Rule | Detail |
|------|--------|
| Application code is **never** changed | Only `.spec.ts` test files are ever patched |
| Healing is bounded | Max 2 heal attempts per test |
| Assertion fixes always need approval | `risky: true` patches pause for human review |
| URL is never guessed | No default site; ambiguous → `BLOCKED` |
| Report language | English always, even for Arabic requirements |
| Terminal statuses | `PASS` · `FAIL` · `BLOCKED` · `ERROR` |
| Failure classes | `Test` (healable) · `Application` · `Environment` · `Infrastructure` |
